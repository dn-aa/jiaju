## 1. 背景与目标（Why）

### 1.1 背景

TP 全屋家居需要一套面向客户与公众的**企业品牌官网**，用于展示品牌实力、产品体系、工程案例、企业动态与人才招聘；同时需要一套**后台管理系统**，让企业内部人员自主维护上述内容，并承接、处理来自官网的预约、留言与简历投递等线索，替代传统人工对接的低效方式。

### 1.2 目标

1. 树立"高端大气"的品牌形象，完整呈现 TP 全屋家居的品牌、产品、案例、新闻与招聘信息。
2. 建立官网 → 线索（预约 / 留言 / 简历）→ 后台处理的闭环，让销售、客服、HR 高效跟进。
3. 内容可维护：非技术人员通过后台即可完成产品、案例、新闻、职位、页面等内容的增删改查。

### 1.3 成功标准（可衡量）

- 官网所有栏目上线后可正常访问，核心页面（首页、产品详情、案例详情、新闻详情、职位详情）**加载时间 ≤ 3 秒**（4G 网络、P95）。
- 后台各模块操作成功率 **≥99.5%**（验收以"无阻断性缺陷"为准）。
- 前台提交的预约 / 留言 / 简历，**100%** 可在后台被检索与处理，无丢失。
- 内容编辑经培训后，可在 **10 分钟内** 独立完成一篇新闻或一个产品的发布。

## 2. 目标用户与角色

### 2.1 前台用户（访客）

- **潜在客户**：想了解品牌、产品、案例，并希望通过预约或留言进一步沟通。
- **求职者**：查看招聘职位并在线投递简历。
- **行业/媒体访客**：浏览企业新闻与行业资讯。
- **经销商/合作方**：了解品牌与联系信息。

### 2.2 后台用户（企业内部）

| 角色 | 职责范围 |
|------|---------|
| 超级管理员 | 全部权限，含账号与角色权限管理 |
| 内容编辑 | 产品、案例、新闻、招聘职位、页面内容、Banner 的发布与维护 |
| 客服 | 在线预约、留言咨询的查看与处理 |
| 招聘专员 | 招聘职位的维护、简历投递的查看与处理 |

> 说明：招聘专员可与内容编辑合并（团队较小时），角色与权限在后台可配置。

## 3. 产品范围

### 3.1 本期范围（In Scope）

- 前台企业展示官网（纯展示，不含在线交易）。
- 后台管理系统（多角色权限）。

### 3.2 非目标（Non-goals，本期不做）

- ❌ 在线商城：购物车、下单、支付、会员体系、订单、多规格 SKU 库存、配送安装、售后退换。
- ❌ 营销工具：优惠券、满减、会员价、积分。
- ❌ 多语言 / 国际化（i18n）。
- ❌ SEO 优化（本期不做，后续可迭代）。
- ❌ 站内全局搜索（后续可迭代；本期仅提供分类/标签筛选）。
- ❌ 第三方物流、B2B 经销商专属入口。

## 4. 技术架构

| 层 | 技术选型 | 说明 |
|----|---------|------|
| 后端 | Python + FastAPI | RESTful API，JWT 鉴权 |
| 前台 | React + Tailwind CSS | 企业官网展示系统 |
| 后台 | React + Ant Design（主题统一为墨色+香槟金，见 §4.1） | 后台管理系统 |
| 数据库 | MySQL 8.0（推荐）/ PostgreSQL | 结构化业务数据 |
| 缓存 | Redis（可选） | 首页热点数据缓存 |
| 文件存储 | 本地磁盘 / 对象存储（OSS） | 图片、简历附件 |
| 部署 | Linux + Nginx + Docker | 前后端分离，反向代理 |
| 通知 | 邮件 / 短信（可选，后续接入） | 预约、简历处理提醒 |

> 前后端分离：前端 React（前台 + 后台两个独立应用），后端 FastAPI 提供统一 API。

### 4.1 设计规范（Design System）

前后台共用同一套视觉语言，确保品牌调性统一（原型已落地：前台官网与后台管理系统均为"墨色 + 香槟金"高端风格）。

- **主色板**：墨色（近黑）`#1C1917`、香槟金 `#B0894F`、米白 `#FAFAF9`；辅助深墨 `#211c17` / `#0d0b09` 用于层次与渐变。
- **字体**：标题 / 品牌名使用衬线字体（Cormorant Garamond / Noto Serif SC）；正文使用无衬线字体（Montserrat / Noto Sans SC）。
- **风格基调**：克制配色、大图留白、优质排版，呈现"高端大气"品牌感。
- **后台实现**：后台组件库沿用 React + Ant Design，但主题（Primary / 侧栏 / 强调色）统一替换为墨色 + 香槟金，取消原 Ant Design 蓝（`#1677ff`）；聚焦态、菜单选中态、图表配色均套用金 / 墨令牌，与前台视觉一致。
- **后台布局**：内容区在侧栏右侧区域内**居中显示且留出对称边距**（原型实现：内容区最大宽 1320px 居中、左右 32px 内边距，卡片在居中区内撑满）；间距遵循统一刻度（卡片内边距 24–28px、区块间 20–22px、表格列 14–16px 内边距、操作链接间 ≥10px），保证页面**居中、和谐、整齐**；表格、Tab、工具栏、统计卡、图表盒等组件间距一致、行距舒展。
- **可达性**：文字与背景对比度满足 WCAG AA（主按钮墨底白字 ≈ 17:1；金色文字对墨底 ≈ 5.4:1）。

## 6. 前台功能需求

> 通用原则：响应式适配（PC 为主、兼顾移动端）；全站风格统一"高端大气"（克制配色、大图留白、优质排版）；所有内容均由后台配置，前台只读。

### 6.1 首页（FR-1）

**用户故事**：作为访客，我希望打开官网首页就能快速了解 TP 是谁、做什么、有哪些亮点，以便决定是否继续深入了解。

- **FR-1.1 品牌首屏**：品牌名、slogan、高端主视觉大图。
- **FR-1.2 Banner 轮播**：多张轮播图（后台可配），可配置标题、副标题、跳转链接。
- **FR-1.3 产品系列入口**：产品系列卡片，点击进入产品中心对应分类。
- **FR-1.4 案例展示入口**：精选案例缩略图，点击进入案例详情。
- **FR-1.5 新闻动态**：最新企业新闻/行业资讯推荐（日期 + 标题）。
- **FR-1.6 品牌实力**：数字/荣誉展示（成立年限、服务客户数、荣誉资质）。
- **FR-1.7 招聘入口引导**：引流至招聘栏目。
- **FR-1.8 预约引导**：首页 CTA 引导至「联系我们」在线预约。
- **FR-1.9 页脚**：版权、ICP 备案号、主导航链接，以及**全局联系信息条**（地址、电话、邮箱、营业时间）；电话可拨号（tel:）、邮箱可发信（mailto:），方便客户在任意页面底部快速获取联系方式（与 FR-6.4.1 同源展示）。
- **FR-1.10 服务流程**：首页展示四步服务流程（预约咨询 → 上门量房 → 方案设计 → 一体化交付），每步含序号、标题与说明，帮助用户理解全屋定制的服务闭环；步骤文案建议后台可配（纳入 BR-6 页面内容管理或新增配置项）。
- **FR-1.11 客户评价**：首页展示客户口碑卡片（头像 / 姓名 / 城市户型 / 五星评分 / 评价内容），增强品牌信任感；评价内容建议由后台维护（纳入 BR-6 页面内容管理或新增"客户评价"内容类型）。

### 6.2 产品中心（FR-2）

**用户故事**：作为潜在客户，我希望按系列浏览产品并查看产品细节，以便判断是否符合我的需求。

- **FR-2.3 产品详情**：多图（主图 + 细节图）、参数表、描述（富文本）、所属系列、关联产品推荐。

### 6.3 新案例展示（FR-3）

**用户故事**：作为潜在客户，我希望看到真实交付效果与设计方案，以便建立信任并参考风格。

- **FR-3.1 案例类型**：客户实景案例、设计方案案例（两类，可筛选）。

### 6.4 新闻（FR-4）

### 6.5 招聘（FR-5）

**用户故事**：作为求职者，我希望查看职位详情并在线投递简历，以便便捷应聘。

- **FR-5.1 分类**：社会招聘、校园招聘两个分类。
- **FR-5.2 职位列表**：职位名称、部门、工作地点、发布时间。
- **FR-5.3 职位详情（JD）**：岗位职责、任职要求、工作地点、薪资范围（社招展示，校招可选）。
- **FR-5.4 在线投递简历**：
  - 通用字段：姓名（必填）、手机号（必填）、邮箱（选填）、应聘职位（自动带出/下拉选择）、个人简介（选填）、简历附件（上传，PDF/Word，≤10MB）。
  - 校园招聘专属字段：学校、学历、专业、毕业时间（选填但建议必填）。
  - 社会招聘专属字段：当前职位、工作年限（选填）。
  - 提交校验：手机号格式校验；附件格式/大小校验。
  - 提交后：提示"投递成功"，后台可查。

## 7. 后台管理功能需求

> 通用原则：登录鉴权（JWT）；角色权限控制；列表页支持搜索、筛选、分页、排序；写操作有二次确认与操作反馈；关键操作记录操作日志。
>
> **交互通用约定（原型已落地）**：
> - **编辑操作**：各管理模块列表的「编辑」操作打开**带现有数据回填的编辑表单**（编辑页/弹窗），保存后更新列表并提示；「+ 新增」操作支持新增后即时上列表。
> - **状态切换**：上架/下架、发布/下架、上线/下线、启用/禁用、招聘中/已暂停等状态在列表行内可直接切换（点击即时生效并 Toast 反馈），无需进入详情。
> - **图片/附件上传**：上传区支持**点击选择本地文件**（含图片管理格点击替换），选择后显示文件名与大小；服务端按类型/大小白名单二次校验（NFR-2）。

### 7.1 登录与权限（BR-1）

- **BR-1.1 登录**：登录名（`username`）+ 密码登录；密码 bcrypt 加密存储（`password_hash`）；禁用账号（`is_activate=0`）不可登录；退出登录。
- **BR-1.2 权限控制**：基于角色的菜单权限 + 按钮/操作权限（RBAC）。
- **BR-1.3 会话管理**：Token 过期、登录态失效处理。
- **BR-1.4 个人中心**：登录用户可维护个人账号——修改密码（校验原密码，新密码 ≥ 6 位且与确认一致）、上传头像（图片类型，≤ 2MB），头像在后台顶栏展示（对应 §9 用户 avatar 字段）。

### 7.2 产品管理（BR-2）

- **BR-2.1 产品系列管理**：新增、编辑、删除（有关联产品时禁止删除）、排序、启用/禁用。
- **BR-2.2 产品管理**：新增、编辑、删除、上下架、排序、置顶。
  - 字段：产品名称、所属空间分类、所属系列（如胡桃木）、产品编号（唯一）、产品描述（富文本）、规格参数（JSON：材质/尺寸/颜色）、封面图片、其它图片（多图）、发布状态（上架/下架/草稿）、是否置顶（0/1）、排序值。
- **BR-2.3 图片管理**：上传、裁剪、替换。上传入口支持**点击选择本地文件**（图片管理页的图片格亦可点击直接替换），选择后显示文件名与大小；校验图片类型与大小（≤ 5MB），防恶意文件。

### 7.3 案例管理（BR-3）

- **BR-3.1 案例管理**：新增、编辑、删除、上下架、排序。
  - 字段：标题、类型（客户实景/设计方案）、风格标签、空间类型、面积、封面图、图集、项目背景、设计说明、关联产品、上下架状态（启用/禁用）。
- **BR-3.2 标签维护**：风格/空间分类字典，供前台筛选。

### 7.4 新闻管理（BR-4）

- **BR-4.1 分类**：企业新闻、行业资讯（固定或可扩展）。
- **BR-4.2 文章管理**：新增、编辑、删除、发布/下架、置顶/推荐。
  - 字段：标题、分类（企业新闻/行业资讯）、封面图、摘要、正文（富文本 HTML）、来源（转载标注）、是否发布（0/1）、是否置顶/推荐（0/1）、发布时间、截止时间、作者。

### 7.5 招聘管理（BR-5）

- **BR-5.1 职位管理**：新增、编辑、删除、上下架、排序。
  - 字段：职位名称、类型（社会招聘/校园招聘）、部门、工作地点、薪资范围（可选）、岗位职责、任职要求、上下架状态（启用/禁用）。

### 7.6 页面内容 / Banner 管理（BR-6）

- **BR-6.1 Banner 管理**：首页轮播图新增、编辑、删除、排序、跳转链接、上下线（启用/禁用）、生效/失效时间（可选）。

  - 关于TP/品牌介绍：富文本 + 图片。
  - 发展历程：时间轴条目（年份 + 事件）增删改排序。
  - 联系我们：联系信息字段（体验中心地址、电话、邮箱、营业时间，与 FR-6.4.1 一致）+ 地图坐标/地址 + 预约时段选项维护；前台「联系我们」页与全局页脚联系信息条共用此配置。

### 7.7 在线预约管理（BR-7）

- **BR-7.1 预约列表**：查看、筛选（时间/状态）、详情。
- **BR-7.2 状态流转**：待处理 → 已联系 → 已完成 / 已取消。
- **BR-7.3 处理记录**：备注跟进情况。

### 7.9 数据看板（BR-9）

> 范围：仅做"线索量"统计，数据直接来自数据库（预约/留言/简历表），**无需前端埋点**。

- **BR-9.1 线索统计**：预约量、留言量、简历投递量（总数 + 按日/周/月趋势）。
- **BR-9.2 线索明细下钻**：从汇总下钻到具体预约/留言/投递列表。

> 说明：看板数据**按角色限定范围**：客服看预约/留言，招聘专员看简历投递，超级管理员看全部线索；内容编辑无看板权限。

### 7.10 系统管理（BR-10）

## 9. 数据模型（核心实体）

> 全表统一通用字段：`id`（主键）、`is_activate`（1 激活 / 0 禁用）、创建人、创建时间、修改人、修改时间；删除采用禁用（is_activate=0）或物理删除（无软删）。字段明细与建表 SQL 见《数据库设计文档》v2.2。

| 实体 | 关键字段 |
|------|---------|
| 用户 User | 登录名 `username`（唯一）、登录密码（bcrypt）、姓名、昵称、手机号、邮箱、性别、岗位、部门编号（dept_id）、角色编号（role_id）、头像（avatar）、最近登录时间 |
| 部门 Department | 部门名称、上级部门（parent_id，0=顶级，支持多级树） |
| 角色 Role | 角色名称、权限集合（permissions JSON） |
| 空间分类 Category | 名称（客厅/卧室/书房/餐厅/全屋）、排序 |
| 产品 Product | 空间分类（category_id）、所属系列、产品编号（唯一）、名称、描述（富文本）、规格参数（JSON）、封面图片 URL、其它图片（JSON）、发布状态（上架/下架/草稿）、是否置顶（0/1）、排序值 |
| 案例 Case | 标题、类型（客户实景/设计方案）、风格、空间、面积、封面、图集、项目背景、设计说明、排序 |
| 新闻 Article | 标题、分类（企业新闻/行业资讯）、封面图、摘要、正文（富文本 HTML）、来源（转载标注）、是否发布（0/1）、是否置顶/推荐（0/1）、发布时间、截止时间、作者 |
| 职位 Job | 名称、类型（社招/校招）、部门、地点、薪资、岗位职责、任职要求、排序 |
| 简历投递 Application | 姓名、手机、邮箱、职位、简介、附件、学校/学历/毕业时间（校招）、工作年限/当前职位（社招）、状态、处理人、处理时间 |
| 预约 Appointment | 姓名、手机、预约日期、时段、备注、状态、处理人、处理时间 |
| 留言 Message | 姓名、联系方式、内容、状态、处理人、处理时间 |
| Banner | 图片、标题、副标题、链接、排序、生效/失效时间 |
| 页面 Page | 页面标识（about/history/brand/contact）、标题、内容（富文本） |
| 操作日志 Log | 操作人、动作、对象类型/ID、详情、IP |

关系要点：User 多对一 Role / Department；Product 多对一 Category（空间分类）；Case 多对多 Product（经 case_products）；Application 多对一 Job；三张线索表（Application/Appointment/Message）通过处理人（processed_by）多对一 User。

## 10. 关键业务规则与流程

### 10.1 线索流程（预约 / 留言 / 简历）

```
访客提交表单（前台校验 + 隐私授权勾选）
    → 数据落库（预约/简历初始状态=待处理；留言初始状态=未读）
    → 后台相应角色可见（列表 + 提醒）
    → 处理人更新状态 + 备注
    → 完成闭环
```

- 前台提交必须通过手机号等格式校验；防刷（图形验证码 + 频率限制）。
- 提交记录不可在前台被他人查看，仅后台可见，且受角色权限隔离。

### 10.2 内容发布规则

- 内容"上架/发布"后才在前台展示；"下架"后前台不可见但数据保留。
- 富文本内容需做 XSS 过滤。
- 图片上传校验类型与大小，防止恶意文件。

### 10.3 权限规则

- 无权限的菜单/操作不展示且后端接口校验拦截。
- 敏感操作（删除、禁用账号）二次确认并记录日志。

## 11. 非功能需求

### NFR-1 性能
- 核心页面 P95 加载 ≤ 3s；接口 P95 响应 ≤ 500ms。
- 支持至少 100 并发访问（一期规模）。

### NFR-2 安全
- 密码加密存储；API JWT 鉴权；接口级权限校验。
- 输入校验 + XSS 过滤 + SQL 注入防护（ORM 参数化）。
- 简历附件上传类型/大小白名单校验，服务端二次校验与隔离存储。
- HTTPS 传输。

### NFR-3 合规与个人信息保护

> 官网通过预约、留言、简历收集访客姓名、手机号、邮箱、简历等个人信息，须符合《中华人民共和国个人信息保护法》（PIPL）等法规。

- **隐私政策**：上线前发布《隐私政策》与《用户协议》，并在表单收集点明确告知 + 获取同意勾选（FR-7.3）。
- **最小化收集**：仅收集业务必要字段；简历等敏感信息单独授权。
- **访问控制**：个人信息仅授权角色可见（客服/招聘专员/超管），后台权限隔离，操作留痕。
- **存储与删除**：明确数据留存期限；提供用户请求删除/更正个人信息的处理通道（如联系邮箱）。
- **安全传输与存储**：HTTPS；附件隔离存储、访问鉴权。
- **ICP 备案**：正式上线前完成 ICP 备案，页脚展示备案号（FR-1.9）；域名、服务器资质合规。
- **地图合规**：使用合规地图服务（如腾讯地图等），坐标采用中国大陆标准地图，不得使用未经审图的地图数据。

### NFR-4 兼容性
- 前台：Chrome / Edge / Safari 主流版本；响应式适配移动端。
- 后台：Chrome / Edge 主流版本（桌面端）。

### NFR-5 可用性 / 易用性
- 后台交互符合 Ant Design 组件规范，视觉主题与前台官网保持一致（墨色 / 香槟金 / 米白，见 §4.1），列表 + 表单 + 状态流转清晰。
- 后台页面**内容居中、布局和谐**：间距/留白遵循统一刻度（见 §4.1 后台布局），表格、标签、操作链接、Tab、工具栏之间距离舒展，避免拥挤或大面积空白。
- 操作有明确反馈与错误提示。

### NFR-6 可维护性 / 可扩展
- 前后端分离，接口文档化（OpenAPI 自动生成）。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 简历附件含恶意文件 | 安全风险 | 类型/大小白名单、服务端校验、隔离存储 |
| 表单被刷/垃圾留言 | 线索质量下降 | 图形验证码、频率限制 |
| 个人信息泄露/不合规 | 法律合规风险 | 隐私政策、最小化收集、访问控制、加密、留存与删除机制（NFR-3） |
| 未完成 ICP 备案 | 无法合规上线 | 上线前完成备案并展示备案号 |
| 地图服务不合规 | 合规风险 | 使用合规地图服务，中国大陆标准地图 |
| 内容维护上手成本 | 使用效率 | 后台模板化表单、富文本编辑器、操作培训 |
