## 1. 项目概述

### 1.1 项目目标

1. 搭建 TP 全屋家居**企业品牌官网（前台展示系统）**：品牌、产品、案例、新闻、招聘、关于我们、联系线索收集。
2. 搭建**后台管理系统**：企业内部多角色（超管 / 内容编辑 / 客服 / 招聘专员）维护内容、处理预约 / 留言 / 简历三类线索、查看线索看板、管理系统账号与权限。
3. 实现"官网 → 线索 → 后台处理"闭环，纯展示不交易。

### 1.2 本期范围（In Scope）

- 前台企业展示官网（纯展示，无在线交易）。
- 后台管理系统（RBAC 多角色权限）。
- 三条线索闭环：在线预约、在线留言、简历投递。

### 1.3 非目标（Non-goals，本期不做，源自 PRD §3.2）

在线商城 / 营销工具 / 多语言 / SEO / 站内全局搜索 / B2B 经销商入口 / 前端埋点 PV·UV（看板仅统计数据库线索量）。

## 2. 技术架构与工程结构

### 2.1 总体架构（依据开发技术文档 §1）

```
客户端（访客浏览器 / 内部用户浏览器）
   ↓ HTTPS
Nginx（静态资源 + 反向代理 /api/*）
   ↓
FastAPI 单服务（内部按 4 个有界上下文分包）
   ├─ 账号域 IAM（auth / sys）
   ├─ 内容域 CMS（products/cases/articles/jobs/banners/pages/...）
   ├─ 线索域 Leads（appointments/messages/applications）
   └─ 看板域 Dashboard
   ↓
MySQL 8.0 + Redis（验证码/限流/缓存） + 对象存储（生产）或本地磁盘（开发）
```

### 2.2 技术栈清单（依据开发技术文档 §4 / ADR-1~9 已锁定）

| 层 | 选型 | 关键说明 |
|----|------|---------|
| 后端 | Python 3.11+ / FastAPI | RESTful、OpenAPI 自动文档、JWT 鉴权 |
| 后端依赖 | SQLAlchemy 2.x + Alembic / Pydantic v2 / pydantic-settings | ORM 参数化防注入、迁移版本化 |
| 后端安全 | bcrypt（cost=12）/ PyJWT / bleach（XSS） / Pillow（验证码） | access 30min + refresh 7d 双 Token |
| 后端限流 | Redis 计数（IP/手机号维度） | 表单提交 5 次/分钟，超限返回 code=3001 |
| 文件存储 | 抽象 StorageBackend：Local（开发）/ S3 兼容·COS（生产） | 图片 ≤2MB、简历 ≤10MB，magic bytes 二次校验 |
| 前台 | React 18 + TypeScript + Vite + Tailwind CSS | 10 个页面，React Query + Zustand，路由懒加载 |
| 后台 | React 18 + TypeScript + Vite + Ant Design 5 | 墨金 theme 覆盖，RBAC 动态路由 + 按钮级权限；看板图表 **ECharts**（墨金定制）、富文本 **wangEditor 5**（已确认选型） |
| 数据库 | MySQL 8.0 / utf8mb4 / InnoDB | 20 张表，通用字段体系，无软删列 |
| 缓存 | Redis 7 | 验证码、限流、首页热点缓存 |
| 本地开发 | Docker Compose 起 MySQL 8.0 + Redis 7 | 已确认（§10-①），开发机无需预装 |
| 部署 | Docker Compose + Nginx + Uvicorn 多 worker | 前后端分离 |

### 2.4 设计规范落地（依据 UIUX v1.2 §2 / §4.1）

- **墨金令牌**：墨色 `#1C1917`、香槟金 `#B0894F`、米白 `#FAFAF9`、浅金灰 `#F5F3EF`、描边 `#E7E5E4`；前台 `design-tokens.ts` + `tailwind.config.ts` 注入；后台 `antdTheme.ts` 覆盖 AntD token（取消 AntD 蓝 `#1677ff`）。
- **字体**：标题衬线 `Cormorant Garamond / Noto Serif SC`；正文无衬线 `Montserrat / Noto Sans SC`。
- **前台容器** 1240px 居中；**后台内容区** max-width 1320px 居中、左右 32px / 上下 28px 内边距，间距刻度按 UIUX §2.3 后台间距表。
- **焦点态**统一金色 2px 焦点环（`rgba(176,137,79,.15)` 3px 晕）；对比度满足 WCAG AA。
- **交互约定**（PRD v2.2 §7 通用 + UIUX §4.3）：编辑操作打开带数据回填的 Modal 表单，新增即时上列表；列表行内状态切换即时生效 + Toast；上传区点击选择本地文件并显示文件名/大小；敏感操作二次确认 + 记操作日志；列表姓名/手机号脱敏展示。

### 2.5 状态语义统一约定（对齐数据库 v2.3 §1.4 + 技术文档 v1.4 §6.5，开发期统一执行）

| 资源 | 上架/上线/启用 | 下架/下线/禁用 | 实现字段 |
|------|------|------|------|
| 产品 products | on 上架 | off 下架（另有 draft 草稿） | `status`（独立发布状态） |
| 新闻 articles | 发布 | 下架 | `is_published`（0/1），发布窗 `publish_at`/`expire_at` |
| 案例 cases / 职位 jobs / Banner / 公告 / 评价 / 服务步骤 | 上架=启用 | 下架=禁用 | `is_activate`（on↔1 / off↔0） |
| 产品系列 categories / 账号 users | 启用 | 禁用 | `is_activate` |
| 全部前台查询 | — | — | 一律叠加 `is_activate=1`；Banner 另须处于 `online_at`–`offline_at` 时间窗内 |

> 后台列表行内状态切换统一走 `PUT /api/cms/{resource}/{id}/status`（body 传 `status: on|off|draft...`），由后端按上表映射到对应字段；账号状态走 `PUT /api/sys/accounts/{id}`。切换即时生效并写 `operation_logs`（action=`{resource}:status_change`）。

## 3. 数据库实施计划

### 3.1 建表（以数据库设计文档 v2.3 为唯一依据，20 张表）

| 域 | 表 | 说明 |
|----|----|------|
| 组织域（4） | users / departments / roles / operation_logs | 用户（username 唯一、password_hash bcrypt）、部门树（parent_id 自引用）、角色（permissions JSON）、操作日志 |
| 内容域（13） | categories / products / cases / case_products / case_styles / articles / jobs / banners / pages / site_config / announcements / reviews / service_steps | 空间分类、产品（product_code 唯一、spec_params/gallery JSON）、案例与关联、风格/空间字典、新闻、职位、Banner（online_at/offline_at）、页面内容、站点配置（单行 id=1）、公告、评价（rating CHECK 1–5）、服务流程 |
| 线索域（3） | applications / appointments / messages | 简历投递、预约、留言（状态机字段 VARCHAR(20)） |

- 全表统一通用字段：`id` + `is_activate` + `created_at`（创建人）+ `created_date` + `updated_at`（修改人）+ `updated_date`。
- 删除语义：禁用（`is_activate=0`）或物理删除，**无软删列**。
- 内容可见性规则（数据库 v2.3 §1.4）：前台一律叠加 `is_activate=1`；产品另须 `status='on'`；新闻另须 `is_published=1` 且在发布窗内。

### 3.2 迁移与种子（数据库设计文档 §7）

- Alembic 版本化迁移（一个变更一个 revision，`upgrade head` 上线 / `downgrade -1` 回滚）。
- 种子数据：部门（5 顶层 + 2 子部门）、角色（4 个：超级管理员/内容编辑/客服/招聘专员，permissions JSON）、初始账号 admin/editor01（bcrypt 强密码部署时生成，首次登录强制改密）、空间分类 5 项（客厅/卧室/书房/餐厅/全屋）、site_config 单行（id=1，地址/电话/邮箱/营业时间/预约时段）、服务流程四步、风格/空间字典 10 项。

### 3.3 已确认补充字段（决策记录，2026-08-19 已确认）

- `users.avatar VARCHAR(512) NULL`：BR-1.4 个人中心上传头像所需。开发技术文档 v1.4 §6.9 待办已解除；**数据库设计文档已升 v2.3 补充该字段**（同步 Mermaid、数据字典、建表 SQL），PRD v2.2 §9 已同步。执行时随 Alembic 迁移一并落地。

- 统一分页 `page/page_size/sort`；统一时间 ISO-8601；枚举见 §2.5 与数据库 v2.3 §6.1。
- OpenAPI 自动生成（`/docs`），前端 `openapi-typescript` 生成 TS 类型，`msw` 并行 Mock。

## 8. 部署方案（依据开发技术文档 v1.4 §10）

- Docker Compose 编排 5 个服务（web:8080 / admin:8081 / api:8000 / mysql / redis）。
- Nginx：静态资源（前台/后台分域名或路径）+ `/api/` 反向代理 + HTTPS（Let's Encrypt）+ 静态长缓存。
- 上线顺序：建库 → `alembic upgrade head` → 种子 → 启动 api。
- 环境变量：DATABASE_URL / REDIS_URL / JWT_SECRET / JWT_ACCESS_TTL(30m) / JWT_REFRESH_TTL(7d) / STORAGE_KIND / OSS_* / CORS_ORIGINS / CAPTCHA_ENABLED(true)。
